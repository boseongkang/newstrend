# Adoption Gate v2 — 매칭 페어 정의 (적용 전 동결)

**이 문서는 데이터에 적용하기 전에 커밋된다.** 이 커밋 이후 정의 변경은
새 버전(v3)으로만 가능하며, 여러 정의를 시도한 뒤 통과하는 것을 고르는
행위는 이 프로젝트가 내내 잡아온 바로 그 패턴이므로 금지한다. 아래 정의는
결과값을 보지 않은 상태에서 통계적 근거만으로 확정했다 (스키마 가용성
확인만 수행: record에 sector 필드 존재, HOLD 포함 전 레코드에
fwd_5d_return 존재).

## 문제 (v1)

v1 게이트는 "시스템 포트폴리오 fold 알파 − always-buy(전체 유니버스)
fold 알파"의 paired NW 검정이다. 두 다리는 **서로 다른 포트폴리오**라서
차이에 구성(composition) 노이즈가 그대로 남는다: NW 등가 sd 6.2pp,
0.5pp 엣지 검출에 ~28개월, 0.2pp에 ~15년. 게이트가 사실상 어떤 현실적
엣지도 판정할 수 없다.

## 정의 (v2)

**단위: 개별 의사결정(deduped record).** dedup된 레코드 i에 대해:

1. **trade set** — v1과 동일 (변경 없음): action ∈ {BUY, WATCH} → s_i = +1,
   {SELL, REDUCE} → s_i = −1, HOLD 제외. r_i = fwd_5d_return.
2. **매칭 페어(counterfactual)** — 같은 anchor date(fwd_5d_anchor_date),
   같은 sector(레코드 자체의 sector 필드)의 **전체 레코드(HOLD 포함)**
   fwd_5d_return 동일가중 평균, **자기 자신 제외**:
   - 같은 anchor·sector의 ex-self 표본이 **5개 이상**이면 섹터 바스켓
   - 미만이면 같은 anchor의 **유니버스 ex-self** 바스켓 (소섹터 fallback —
     n<5 섹터 평균은 노이즈라는 기존 표시 정책과 동일 근거)
3. **페어 차이**: d_i = s_i · r_i − r̄_basket(i)  (×100 = pp)
4. **집계·검정**: d_i를 anchor date별 평균 → fold 시계열 {d_t};
   Newey-West lag-4 t-검정 (5일 중첩 수익률의 시계열 의존 — v1과 동일 처리).
5. **판정**: mean(d) > 0 **AND** NW p < 0.05 → PASS.

## 통계적 근거 (사전, 결과 무관)

1. **분산 분해**: 5일 개별 수익률 = 시장·섹터 공통성분 + 개별성분.
   같은 날·같은 섹터 바스켓 차감은 공통성분을 기대값에서 정확히 제거한다.
   v1은 SPY만 차감 + 서로 다른 두 포트폴리오 비교라 공통성분의 잔차와
   구성 노이즈가 남는다. 분산 축소는 구조적 귀결이며, 실제 축소 폭은
   적용 후 측정해 보고한다 (사전 예단하지 않음).
2. **ex-self 제외**: 자기 자신을 바스켓에 넣으면 d_i가 기계적으로 0 쪽으로
   수축(특히 소섹터). 제외가 "동료 대비" 질문의 불편(unbiased) 선택.
3. **동일 데이터·동일 방법론**: 바스켓 수익률을 레코드 테이블 자체에서
   취해(trade 다리와 같은 fwd_5d_return 산출) 가격 소스/배당/정렬 불일치를
   원천 배제. 레코드의 sector 필드를 쓰므로 예측 시점의 섹터 라벨과 일치.
4. **fold 집계 유지**: anchor date별 평균 후 NW lag-4 — v1과 동일한
   시계열 의존 처리를 유지해 v1과의 차이가 페어링 정의 하나로 귀속되게 함.

## 해석 변경 (선언)

v2의 귀무가설은 v1과 다르다: v1 = "전체 유니버스 always-buy를 이긴다",
v2 = "**같은 섹터의 무선택 롱 바스켓**을 이긴다" — 더 엄격한 비교 대상
(섹터 베타로 얻는 수익을 공으로 인정하지 않음). 따라서 v1/v2의 점추정
수치는 레벨이 비교 불가하며, **sd가 줄어 유의해지는 것과 성능이 좋아지는
것은 별개다**. v2로의 전환은 측정 정밀도의 개선이지 시스템 평가의 완화도
강화도 아니다.

## 운영

- validate.py의 `gate`가 v2가 된다 (필드명 유지 + `version` 표기).
  v1은 `gate_v1_legacy`로 병행 보고 (연속성·비교용).
- CLAUDE.md의 unfreeze 조건 중 게이트 참조는 v2를 가리키게 되며, 이 변경
  자체가 사전 등록 원칙의 적용 대상이므로
  config/checkpoint_registration.json에 append로 기록한다 (정의 동결 커밋
  해시 + 적용 후 측정된 sd/MDE 포함).
- CP-2026-11-01 체크포인트의 판정 지표(live-sentiment forward alpha
  점추정)는 게이트가 아니므로 **영향 없음**.

# 결과 (2026-08-06 적용) — 가설 기각, v1 원복

동결(aff11ec6d) 후 적용 결과:

| | v1 | v2 |
|---|---|---|
| 판정 | FAIL (−0.88pp, p=0.261) | FAIL (−0.94pp, p=0.337) |
| NW 등가 sd | 6.19pp | **7.77pp (악화)** |
| MDE @ n=61 | 1.55pp | 1.95pp |

**절차는 성공** (정의 동결 → 적용 → 부정 결과 그대로 기록),
**가설은 기각** (섹터 매칭이 sd를 줄이지 못함).

**원인 — short 페어 대수 오류**: s=−1일 때 d = s·r − basket = −(r+basket)
이 되어 섹터·시장 공통성분이 상쇄가 아니라 **2배로 진입**한다. 분해 진단:
long 페어만의 fold sd는 3.30pp로 가설대로 축소, short 페어는 14.18pp.
이 오류는 데이터 없이 대수 전개만으로 사전에 잡을 수 있었다.

**교훈: 페어 정의는 부호별로 대수 전개를 먼저 검증할 것.** d_i를 s=+1과
s=−1 각각에 대해 공통성분 계수까지 풀어 쓰고, 모든 부호에서 공통성분이
소거되는지 확인한 뒤에 동결한다.

**운영 게이트는 v1로 원복** (validation.json: gate=v1, gate_v2_failed 병행
보존). 양쪽 판정이 FAIL로 동일하므로 결과 기반 선택(verdict-shopping)이
아니며, 정밀도가 나쁜 쪽을 운영 게이트로 둘 이유가 없다는 정밀도 근거다.

# v3 — 정의 기록만, 보류 (동결·적용 안 함)

**정의(기록용)**: short 페어를 d_i = s_i·(r_i − basket_i)로 수정 — 모든
부호에서 공통성분이 소거된다. long 분해 sd 3.30pp가 시사하는 잠재력:
전체 sd가 ~3.3pp 수준이면 MDE@61이 1.55 → **0.83pp**로 개선될 수 있다.

**보류 근거**:
- (a) v2 실패 직후의 재시도는 반복 시행의 시작점이다 — 정의를 결과에
  맞춰 고치는 패턴이 된다.
- (b) ml_monitor forward가 n=5,040, p≈0.0000으로 반증이 단단한 상황에서
  게이트 정밀도 개선이 결론을 바꿀 확률은 낮다. 병목은 게이트 sd가
  아니라 **점추정의 부호**다.
- (c) 11월 체크포인트에서 점추정이 양수로 돌아섰을 때 비로소 정밀도가
  병목이 된다. 그때 동결 절차(정의 커밋 → 적용)로 재개한다.
